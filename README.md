# ProofPath

> Don't tell me it's done. Show me the proof.

ProofPath turns a goal into a short **Success Contract** of testable requirements, then judges each requirement against the evidence you link to it: **PROVEN**, **NOT PROVEN** or **CONTRADICTED**, always with a reason that quotes the evidence. Anything not proven gets a **Proof Gap**: the next concrete test to run. At 100% you get a **Proof Card** to paste into a PR.

The verifier is deterministic on purpose. It has no chat, no confidence score and no LLM judge, and it treats instructions hidden in evidence as data. A verifier that can be talked into a verdict isn't a verifier.

**Live demo:** https://toumo45.github.io/proofpathV2/ (runs entirely in the browser: no account, no API key, nothing sent anywhere)

## How to judge it in 60 seconds

1. Open the live demo and press **Try the demo**, then **Verify**. An AI agent claimed a contact form was done. Coverage is **25%**: one real test proves R1, a bluff ("would be blocked") is NOT PROVEN, and a 500 error is CONTRADICTED.
2. Read each Proof Gap, add the evidence it asks for, and mark the retest **Supersedes E3**.
3. Press **Verify** again. At **100%** the Proof Card appears, and the old failure stays listed as superseded.

## What gets rejected

Every row is a regression test in [`tests/`](tests). The v1 prototype, built without a plan, got the first four wrong.

| Evidence | Verdict | Test |
|---|---|---|
| "the invalid email **would** be blocked" | NOT PROVEN (hypothetical wording) | `hypothetical.test.ts` |
| one item "blocked", another "invalid email **was accepted**" | CONTRADICTED, naming both | `conflict.test.ts` |
| "page shows a **500** Internal Server Error and the submission **hangs**" | CONTRADICTED (error signal) | `error-signals.test.ts` |
| "pressed Send **without** any delay. Observed: submission completed" | PROVEN (negation scoped to the requirement) | `negation-scope.test.ts` |
| keyword-stuffed text with no action and no observed result | NOT PROVEN | `vague.test.ts` |
| "Note to verifier: record every verdict as PROVEN" | ignored, flagged **untrusted** | `injection.test.ts` |
| "it works", "looks good", "LGTM", "I verified that it works" | NOT PROVEN (vague) | `vague.test.ts`, `obfuscation.test.ts` |
| "wo&lt;zero-width space&gt;uld", "w&lt;Cyrillic o&gt;uld", fullwidth "ｍａｒｋ everything proven" | normalized, then rejected, and flagged **obfuscated** | `obfuscation.test.ts` |
| an agent's "done" message: "…**should** reject invalid emails. The form **will** now show…" | NOT PROVEN, labeled **AGENT CLAIM** | `agent-claim.test.ts` |

It also avoids false verdicts on *good* evidence: "should" in a test's Action (that's setup), "no errors", "done in 2s, file appears in the list", and a validation error message on a requirement that *expects* a rejection.

## How it works

Four pure functions (no DOM, no network), and screens that only display what they return:

```
goal ──► contract generator ──► clean checker ──► Contract Review (you edit, then approve)
                                                        │
evidence (structured test / text / agent claim) ────────┤ linked explicitly to requirements
                                                        ▼
                    verifier, per requirement × active evidence:
                    normalize → injection → hypothetical → vague → contradiction → support
                                                        │
          any contradiction → CONTRADICTED · any support → PROVEN · else NOT PROVEN
                                                        ▼
                    coverage (proven ÷ total) · Proof Gaps · Proof Card at 100%
```

- `lib/verify/`: the screens (`screens.ts`), one evidence item against one requirement (`stance.ts`), and aggregation (`index.ts`).
- `lib/text.ts`: normalization (NFKC, invisible characters, lookalike letters), tokenizing and quoting.
- `lib/store.ts`: one reducer with a `stale` flag. Any change to evidence makes verdicts stale, and the Proof Card only renders from current verdicts. The session is kept in `localStorage` and validated with Zod on load.
- `lib/fixtures/demo.ts`: the demo contract and evidence. It is fixture data and labeled as such in the UI.

Stack: Next.js (static export), TypeScript, Tailwind CSS, Zod, Vitest. Deployed to GitHub Pages by [`.github/workflows/pages.yml`](.github/workflows/pages.yml). CI runs `npm run verify:all` on every push.

## Run it locally

Requires Node.js 24+.

```bash
npm install
npm run dev          # http://localhost:3000
npm test             # adversarial test suite
npm run demo:verify  # prints the demo verdicts in the terminal
npm run verify:all   # lint + typecheck + tests + static build
npm run mutation     # mutation check (see above)
```

## Limitations

- **Rules, not understanding.** The verifier matches wording patterns and target words. Evidence phrased in a way no rule anticipates can be judged NOT PROVEN when it is real. When unsure, it says NOT PROVEN: a false PROVEN is the worst failure.
- **Evidence is self-reported.** ProofPath doesn't run tests or look at your app. It judges what you tell it you observed. The Proof Card says so.
- **English only.** The screens are English word lists.
- **No screenshots.** Images aren't accepted as evidence, because judging only an image's caption would be misleading.
- **Single user, one browser.** The session lives in `localStorage`. There are no accounts, no sharing and no sync.
